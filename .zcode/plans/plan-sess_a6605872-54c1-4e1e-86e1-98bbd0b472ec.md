## 1. New: `web/static/css/tokens.css`

The design system. Tokens only — **no component rules** — so the "appearance lives in app.css" rule from `app.css:21-28` is preserved.

**Palette.** Primitives mirror today's values exactly (no visual change): navy 50→950, teal 100/500/600/700, emerald-600, gold 300/500/600. Then semantic aliases that both Tailwind config and component CSS consume:

```
conform      fg --psa-state-conform-fg      / bg / border
nonconform   fg --psa-state-nonconform-fg   / bg / border / bar / solid
review       fg --psa-state-review-fg       / bg / border
processing   fg --psa-state-processing-fg   / bg / border
required     -> neutral family (demoted)
```

`--psa-state-nonconform-fg` light = `#dc2626` (**4.83:1** on white — passes; keeps today's look), dark = `#fca5a5` (**9.08:1** on `#121b2c`). Today this value is hardcoded with no dark override, which is why it measures 3.89:1 in dark mode — the token removes the failure while preserving the light-mode appearance.

**Type scale** — 7 steps replacing 28 ad-hoc values (0.68/0.7/0.72/0.74/0.76/0.78rem all deleted):

```
2xs 12px  labels, meta, chips      xl  22px  section titles
xs  13px  hints, captions          2xl 28px  page title (fluid clamp)
sm  14px  secondary body
base 16px body  <- was 15px desktop / 14px mobile
lg  18px  card titles
```

**Space scale** — `--psa-space-1..16` (4→64px, 4px rhythm) plus semantic aliases that kill the 5-different-card-paddings problem: `--psa-pad-card`, `--psa-pad-card-sm`, `--psa-pad-control`, `--psa-stack-section`, `--psa-gap-inline`. Tailwind's numeric spacing scale is **left alone** (150+ template usages depend on it) — I'll document explicitly that Tailwind numerics are the template-level spacing scale and `--psa-space-*` is for component internals.

**Radius/shadow/motion** — existing `--radius-xs..xl` kept, plus `--psa-radius-pill` (replacing the scattered `999px` literals), `--psa-radius-control`, `--psa-radius-card`. Shadows kept, plus `--psa-shadow-focus`: a **two-layer halo** (`0 0 0 2px var(--psa-surface), 0 0 0 4px var(--psa-focus)`) so the ring stays visible against both the page *and* a teal/gold-filled control — this is the M8 fix, and it satisfies the 3-4px guidance. Motion gets named durations and easings.

**Migration strategy — aliases, not a mass rename.** `app.css` references `var(--color-*)` ~200 times; a mechanical rename risks silent `var(--undefined)` drops. So tokens.css defines each `--psa-*` value once and `app.css` keeps `--color-surface: var(--psa-surface)` etc. as documented aliases. One source of truth, zero breakage, incremental migration. Legacy names stay supported.

## 2. New: `web/templates/components/tailwind_config.html`

The current config (`base.html:47-72`), with `brand`/`navy`/`gold` re-pointed at `var(--psa-*)`, a new `state` family, and `fontSize` bound to the type tokens.

Two deliberate constraints, both from verified findings:
- **Tailwind's default `slate`/`emerald`/`amber`/`red` scales stay untouched.** `bg-slate-50/70` and `bg-slate-50/50` are in use; in Tailwind v3 an opacity modifier on a `var()`-defined colour does not compose, so binding those scales would silently break those two classes and the dark-mode mapping at `app.css:2307-2311`.
- `fontSize` is bound as `['var(--psa-text-xs)', { lineHeight: … }]`. This is the mechanism for the 16px floor with no template edits. Tailwind emits `fontSize` before `lineHeight`, so the existing `leading-*` overrides in templates keep winning. **Verify first**: if the CDN does not emit `font-size: var(...)` as expected, the fallback is to set the scale on `html` and map component sizes in `app.css` — overriding `.text-xs` directly in `app.css` is *not* viable, because the CDN injects its stylesheet at runtime and would win the cascade (exactly the ordering hazard `app.css:21-28` documents).

Also adding an `xs: 480px` screen (currently an ad-hoc breakpoint in CSS, absent from Tailwind, while `sm`/`lg` already align).

## 6. New: `tests/test_design_tokens.py`

The CSS comments at `base.html:19` and `app.css:2273` both claim `tests/test_dark_theme.py` guards this. **That file does not exist** — I verified there is no dark-theme test, no test reads `app.css` contents, and no test pins any token, class or the Tailwind config. This is the highest-leverage addition, because it would have caught H2, M6 and M7:

1. Every `var(--psa-*)` / `var(--color-*)` referenced in either stylesheet resolves to a defined property → catches migration typos (the `var(--undefined)` silent-drop hazard).
2. Every `--psa-state-*-fg` has a `[data-theme="dark"]` override → dark parity.
3. No raw hex/rgb outside `tokens.css` (explicit allowlist) → prevents M7 recurring.
4. **Computed contrast** (pure-Python WCAG, no dependencies) for a declared table of fg/bg token pairs: ≥4.5:1 text, ≥3.0:1 non-text — including the gold-solid avatar pair that failed at 1.44:1.
5. `[data-theme="dark"]` overrides only custom properties → enforces the documented token-only dark theme.
6. RTL lint: no `text-align: left|right`, `margin-left/right`, `padding-left/right` outside a documented LTR-isolation allowlist; `dir="rtl"` on `<html>`; every directional gradient uses `to left` or a `--psa-gradient-*` token.
